# Soma implementation plan

> Implement one task at a time. Review each deliverable before starting the next. Steps use `- [ ]`.

**Goal:** move axon's model access into a new module, soma, usable in-process by axon and as a per-person server that remote axon sessions call.
**Architecture:** soma's root module holds the shared types, provider code, logins, a wire format, an HTTP handler and a client provider, all on the standard library. A nested module at `cmd/soma` holds the program with Tailscale. Axon imports the root module, keeps aliases for the moved types, and gains a `soma` provider kind.
**Source:** `docs/designs/soma.md` in this repository. Scenario numbers below refer to it.

Two repositories are touched. Tasks marked **[soma]** run in `/Users/leonhardbreuer/Developer/soma`, tasks marked **[axon]** in `/Users/leonhardbreuer/Developer/axon`. Run them in the order written: S1, A1, S2 to S7, A2, S8, S9, A3.

## Decisions

- Soma owns the provider code; axon imports soma. Soma must not depend on axon, and axon must still work with no server.
- The wire carries axon's own types as explicit JSON types with an integer version. No OpenAI-compatible API, because translation loses thinking and replay data.
- Streaming HTTP on the standard library. No WebSocket: a spike passed axon's whole suite without one.
- One server serves one person: one token, one root, no user accounts. Isolation comes from one container per person.
- The repository holds two modules. The root module requires nothing outside the standard library, so axon inherits nothing. `cmd/soma` is a nested module and the only place that requires `tailscale.com`.
- File formats (`models.json`, `auth.json`, catalog and models.dev caches) and axon's root `~/.axon` do not change. Soma's library takes the root as a parameter, as `internal/auth/store.go` in axon already does.
- Local mode must not change in any observable way, including message texts and the user agent. The program name is a package variable the embedding program sets, following the existing pattern of `wire.Version`, `auth.Issuer`, `auth.LoginPorts` and `auth.OpenBrowser`.
- The session log records the entry's name; the client rewrites it to the upstream's name in the messages it sends (scenario 5). Axon stamps the name after the provider returns (`internal/agent/agent.go:858`), and the Claude provider matches its own replies by name (`internal/provider/claudecode/plan.go`, `decide`).
- Soma never reads, stores or forwards Claude Code's credentials.
- Axon's second test pass uses a hidden `testsoma` command of axon's own test binary, so axon never builds `cmd/soma`.
- The moved code keeps its file structure and its unit tests move with it. Do not restructure it.

## Constraints

- Go version: `go 1.27` in every `go.mod`, matching axon.
- Soma's root `go.mod` has no `require` block at any commit. Verify with `grep -c '^require' go.mod` printing `0`.
- Axon's allowed dependencies after this plan: the standard library, `golang.org/x/term`, `golang.org/x/sys`, `github.com/rivo/uniseg`, `go.starlark.net`, and `github.com/cheetahbyte/soma` (root module only).
- Axon check: `./scripts/check.sh` must pass at the end of every [axon] task. Soma check: `./scripts/check.sh`, created in S1, must pass at the end of every [soma] task.
- Tests use temporary roots and reach nothing beyond localhost. No real keys or paid APIs.
- Axon's idle rule (no ticker, sleep loop or polling read while waiting for input) still binds axon, including the soma client inside it. It does not bind the soma server.
- Soma has no git repository yet. Ask the owner before `git init`. Commit only if the owner has approved commits; then one commit per task, Conventional Commits, staging only the task's files. Push nothing.
- Until the owner publishes soma, axon builds against it through an untracked `go.work` in the axon directory listing `.` and `../soma`. Add `go.work` and `go.work.sum` to `.git/info/exclude`, not to `.gitignore`. Axon's `go.mod` gains no `replace` directive at any point.
- Record step results and deviations in this file's Deviations section, for both repositories.
- Comments: none by default; when one is needed, why only, at most three lines.

## Out of scope

- The workspace manager, axon's `/remote`, and worktree sessions.
- User accounts, per-sandbox tokens, spending caps, an admin interface.
- A longer retry budget in axon for soma network errors.
- Usage reporting for toktrack: no usage log, no `usageLog` setting, no toktrack in the image. The owner deferred it.
- Pruning Claude's conversation files.
- One setting that mounts all of a server's providers in axon.
- Moving axon's provider behavior tests out of `e2e/` into soma. The spec allows it "over time"; this plan leaves them where they are.
- Refactoring any moved code beyond what a task names.

## Review focus

1. **Entry name differs from upstream, with Claude.** An entry `home` with `upstream: "claude"`: the second run must resume the same Claude conversation, and the session log must say provider `home`. Test in S2 (`TestNamesAreTranslated`) and in A2's second pass.
2. **Login after the server started.** A request fails for a missing login, the login file is written, and the next request succeeds without a restart. Test in S6.
3. **A dropped stream during a Claude turn, then a retry.** The retry must start a new Claude conversation from the sent messages; the fake `claude` must not receive `--resume`. Test in S5.
4. **An old catalog cache file** without the conversation field must read as "does not keep the conversation" and must not fail to parse. Test in S2.
5. **Secrets in the `claude` child.** With `SOMA_TOKEN` and `TS_AUTHKEY` set on the server, the fake `claude`'s recorded environment contains neither. Test in S6.
